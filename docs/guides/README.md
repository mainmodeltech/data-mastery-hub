## Quel guide pour quelle personne ?

Une personne qui **cumule** plusieurs profils lit **les guides de chacun** (ex. Admissions + Finance : guides 02 et 03). Le **menu** de la plateforme montre à chacun exactement ce que ses profils autorisent : si une page décrite dans un guide n'apparaît pas, c'est que le profil ne la donne pas.

## Ce que ces guides couvrent (et ne couvrent pas)

- **Couvert** : le back-office et l'espace apprenant, tels que livrés (profils et droits, séparation des tâches, journal d'audit, candidatures à grande échelle, certificats à valider, tentatives de quiz, communauté avec code formaté, masterclass par événements, plafond de parrainage à 30 %).
- **Hors périmètre** : l'exploitation technique (déploiement, sauvegardes, supervision), documentée dans `docs/ops` côté backend, et le guide de recette `docs/recette/guide-recette-staging.md` qui sert à **tester** la plateforme plutôt qu'à l'**utiliser**.

## Tenir les guides à jour

Les guides décrivent les **réglages de départ** des profils. Si la Direction modifie les droits d'un profil (matrice des droits), mettre à jour le tableau des menus dans [00 — Bases communes](00-bases-communes.md) et le guide concerné.
